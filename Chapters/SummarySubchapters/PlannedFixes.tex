\subsection{Bugfixes (Jakub Jędrzejczyk)}
\label{sec:Bugfixes}

Despite our best efforts to test the code before finalizing the release for user testing purposes, a few bugs have been identified that ought to be addressed, should work continue on this project.

The most glaring issue was the fact that the AMD CPU compatible motherboard's RAM slots fail to connect to any of the available RAM modules.
This was because during the component creation process, only DDR4 RAM modules were created, whereas the AMD motherboard required DDR5 modules.
While this could be treated as an intentional limitation, forcing a user to ensure they pick compatible components, it introduces an unnecessary punishment that is not telegraphed to the user appropriately.

Another issue is that sometimes if a slot overlaps two slots (one valid, one invalid to place the part in, as shown in figure \ref{fig:ErrorsSlotOverlap}), as opposed to it only overlapping a single valid slot (see figure \ref{fig:ErrorsNoSlotOverlap}), the connected component might end up attached to the invalid slot instead of the valid one, if the user decides to make the connection.
During testing, users were instructed to do their best to ensure a component's slot only overlapped a single, valid slot, but we recognize that this is not a viable, long-term solution.
This issue may stem from unexpected behavior in the event binding algorithm, and will require further investigation.

While connections between components work as intended, there is a rare bug in which the component being connected may end up moving not towards the slot it is being connected to, but rather slightly behind it (figures \ref{fig:ErrorsCPUBehindMotherboard} and \ref{fig:ErrorsCPUBehindMotherboard2}), or in the very center of the target component, i.e. the parent of the target slot (figures \ref{fig:ErrorsCPUMiddleMotherboard} and \ref{fig:ErrorsCPUMiddleMotherboard2}).
Given how otherwise reliable this functionality is, this appears to be an issue with the object alignment algorithm, as object parent assignments are handled correctly, even if the visual placement is not.

These are all the bugs that have been identified so far.
Whereas the first would be easy to fix, either by repurposing an existing RAM component into DDR5 or adding a new DDR5 RAM component, the other two will require further investigation and testing to ensure they are properly resolved.
Fortunately, none of these bugs make it impossible to use the application, though in the context of an otherwise polished product, they do detract from the overall user experience.
As known and documented issues, these would be the first to be addressed, should further development of the project be undertaken.
